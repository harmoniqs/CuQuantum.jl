CuDensityMat API Reference

CuQuantum.CuDensityMat — Module
CuDensityMat

Julia bindings for NVIDIA's cuDensityMat library — high-performance density matrix simulation for analog quantum dynamics (Lindblad master equation, time-dependent Hamiltonians, backward differentiation/gradients).

Part of the CuQuantum.jl package. Targets cuDensityMat 0.7 (cuQuantum 26.9).

source
CuQuantum.CuDensityMat.MIN_LIBRARY_VERSION — Constant

CuQuantum.CuDensityMat.compute_operator_action_backward! — Method
compute_operator_action_backward!(ws, operator, state_in, state_out_adj,
    state_in_adj, params_grad; time=0.0, batch_size=state_in.batch_size,
    num_params=0, params=nothing)

Compute backward differentiation (the VJP) of a single-operator action ρ_out = A(θ) ρ_in.

Gradient convention

Adjoints are holomorphic-side gradients, ∂L/∂Re z − i ∂L/∂Im z (= 2 ∂L/∂z), the elementwise conjugate of the ChainRules/Zygote cotangent ∂L/∂Re z + i ∂L/∂Im z. For a real cost L(ρ_out) pass state_out_adj = ∂L/∂Re ρ_out − i ∂L/∂Im ρ_out; locally this is the bilinear cost L = Re Σᵢⱼ state_out_adjᵢⱼ ρ_out,ᵢⱼ = Re Tr(state_out_adjᵀ ρ_out) (the seed is not conjugated). Then:

  • state_in_adj += A(θ)ᵀ state_out_adj, the same kind of gradient with respect to ρ_in (chain it into the previous step's state_out_adj);
  • every gradient callback receives the holomorphic adjoint of its quantity Q (scalar coefficient or operator tensor), ∂(Σ state_out_adj ∘ ρ_out)/∂Q — for a scalar callback this includes the static coefficient it multiplies — and must accumulate params_grad[n] += Re(Σ adjoint .* ∂Q/∂θ[n]), with no factor 2.

To use a ChainRules cotangent ρ̄, pass conj.(ρ̄) and conjugate the returned state_in_adj; params_grad needs no change.

The cuDensityMat header documents 2·Re(...): that is the same number for the Wirtinger seed state_out_adj = ∂L/∂ρ_out, half of the seed above. The convention was measured on an A10 (libcudensitymat 0.7.0) and is pinned against finite differences of the GPU forward action, with factor-2, conjugation and conjugated-seed negative controls, in test/densitymat/test_gradients.jl.

Arguments

  • state_in: Forward-pass input state
  • state_out_adj: Adjoint of the forward-pass output, ∂L/∂Re ρ_out − i ∂L/∂Im ρ_out
  • state_in_adj: Output — receives ∂L/∂Re ρ_in − i ∂L/∂Im ρ_in (accumulated, += semantics)
  • params_grad: GPU vector — receives the parameter gradients from the gradient callbacks (accumulated, += semantics; zero it before the first call)

CuQuantum.CuDensityMat.compute_spectrum! — Method
compute_spectrum!(ws, spectrum, num_eigenstates, eigenstates, eigenvalues;
    time=0.0, batch_size=1, num_params=0, params=nothing,
    tolerances=fill(sqrt(eps(Float64)), num_eigenstates * batch_size)) -> tolerances

Compute eigenvalues and eigenstates.

Arguments

  • num_eigenstates: Number of eigenvalues/eigenstates to compute (≤ max from prepare)
  • eigenstates: Vector of num_eigenstates pre-allocated AbstractStates. Their contents are the initial guesses of the first Krylov block and must be linearly independent (in particular, not zero); on return they hold the eigenstates.
  • eigenvalues: GPU array of length num_eigenstates * batch_size with the element type of the states (ComplexF64 for complex states, even for Hermitian operators; the library writes values of the state data type).
  • tolerances: Requested convergence tolerances (CPU, Float64), one per eigenstate.

Returns

  • The achieved solver residual norms, one per eigenstate (Vector{Float64}).

CuQuantum.CuDensityMat.create_operator_spectrum — Method
create_operator_spectrum(ws, operator;
    is_hermitian=true,
    spectrum_kind=CUDENSITYMAT_OPERATOR_SPECTRUM_LARGEST_REAL) -> OperatorSpectrum

Create an extreme-eigenspectrum (block Krylov) solver for the given operator.

Arguments

  • is_hermitian: Whether the operator is Hermitian (the library trusts the flag)
  • spectrum_kind: Which eigenvalues to compute:
    • CUDENSITYMAT_OPERATOR_SPECTRUM_LARGEST_REAL — largest real part (default)
    • CUDENSITYMAT_OPERATOR_SPECTRUM_SMALLEST_REAL — smallest real part
    • CUDENSITYMAT_OPERATOR_SPECTRUM_LARGEST — largest by magnitude
    • CUDENSITYMAT_OPERATOR_SPECTRUM_SMALLEST — smallest by magnitude

cuDensityMat 0.7 only implements Hermitian operators with the *_REAL kinds (the same two that cuQuantum Python exposes, as "LA"/"SA"); the by-magnitude kinds and is_hermitian = false make cudensitymatCreateOperatorSpectrum return CUDENSITYMAT_STATUS_NOT_SUPPORTED, which is rethrown here as an ArgumentError naming the supported configuration. The solver further needs non-batched dense pure states in double precision, and a Hilbert space larger than the Krylov subspace (see prepare_spectrum!).

CuQuantum.CuDensityMat.wrap_scalar_callback — Method
wrap_scalar_callback(f; gradient=nothing, device=:cpu) -> (cb, gcb, refs)

Wrap a Julia function as a scalar callback for time-dependent coefficients.

Arguments

  • f: the coefficient function. For device = :cpu, f(time::Float64, params::Matrix{Float64}, storage::Vector{T}) computes on the host; for device = :gpu, f(time::Float64, params::CuDeviceMatrix{Float64}, storage::CuDeviceVector{T}, stream::CuStream) enqueues CUDA.jl kernels on stream (e.g. @cuda stream=stream kernel(storage, params, time)) and returns without synchronizing. T matches the operator's data type, params is (numParams, batchSize) and storage is (batchSize,). Write the coefficient values into storage.
  • gradient: Optional gradient function, g(time, params, scalar_grad, params_grad) on the CPU, or g(time, params, scalar_grad, params_grad, stream) on the GPU. scalar_grad[b] is the holomorphic adjoint of the coefficient f, input only; the function accumulates params_grad[i, b] += real(scalar_grad[b] * ∂f[b]/∂params[i, b]) — Re, with no factor 2, in the gradient convention of compute_operator_action_backward!.
  • device: :cpu (CUDENSITYMAT_CALLBACK_DEVICE_CPU) or :gpu (CUDENSITYMAT_CALLBACK_DEVICE_GPU); applies to both f and gradient.

Returns

  • cb::cudensitymatWrappedScalarCallback_t — the callback struct
  • gcb::cudensitymatWrappedScalarGradientCallback_t — the gradient callback struct
  • refs — opaque reference holder (keep alive while callback is in use)

Example

# Time-dependent coefficient: f(t) = exp(iΩt) where Ω = params[1,:]
function my_coeff(time, params, storage)
    for i in axes(storage, 1)
        ω = params[1, i]
        storage[i] = complex(cos(ω * time), sin(ω * time))
    end
end
cb, gcb, refs = wrap_scalar_callback(my_coeff)

# The same on the GPU
function cis_kernel!(storage, params, t)
    i = threadIdx().x

CuQuantum.CuDensityMat.wrap_tensor_callback — Method
wrap_tensor_callback(f; gradient=nothing, device=:cpu) -> (cb, gcb, refs)

Wrap a Julia function as a tensor callback for time-dependent operator elements.

Arguments

  • f: f(time::Float64, params::Matrix{Float64}, storage::Array{T}) for device = :cpu, or f(time, params::CuDeviceMatrix{Float64}, storage::CuDeviceArray{T}, stream::CuStream) for device = :gpu (enqueue kernels on stream, don't synchronize). storage has shape (d1, d2, ..., d1, d2, ..., batchSize) for dense operators. Write the tensor elements into storage.
  • gradient: Optional gradient function, g(time, params, tensor_grad, params_grad) (CPU) or g(time, params, tensor_grad, params_grad, stream) (GPU). tensor_grad has the shape of storage and holds the holomorphic adjoint of the tensor; the function accumulates params_grad[i, b] += real(sum(tensor_grad[.., b] .* ∂storage[.., b]/∂params[i, b])) — Re, no factor 2, see compute_operator_action_backward!.
  • device: :cpu or :gpu, see wrap_scalar_callback.

Returns

  • cb::cudensitymatWrappedTensorCallback_t
  • gcb::cudensitymatWrappedTensorGradientCallback_t
  • refs — opaque reference holder
