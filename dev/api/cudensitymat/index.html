CuDensityMat API Reference

CuQuantum.CuDensityMat — Module
CuDensityMat

Julia bindings for NVIDIA's cuDensityMat library — high-performance density matrix simulation for analog quantum dynamics (Lindblad master equation, time-dependent Hamiltonians, backward differentiation/gradients).

Part of the CuQuantum.jl package. Targets cuDensityMat 0.7 (cuQuantum 26.9).

source
CuQuantum.CuDensityMat.DEFER_DESTROY_UNTIL_CLOSE — Constant

When true (default), GC-reclaimed objects are destroyed only when their WorkStream is closed or collected, never while it is still in use. On the A10 (libcudensitymat 0.7.0) destroying a prepared operator and then building/preparing another one on the same library handle aborted inside the library ("TensorNetwork::placeTensor: Connections are invalid") or hung; deferring the destroys to the end of the WorkStream's life avoids it at the cost of keeping the dead objects' (host-side) library structures until then. Set CuDensityMat.DEFER_DESTROY_UNTIL_CLOSE[] = false to destroy as soon as possible (in dependency order).

source
CuQuantum.CuDensityMat.MIN_LIBRARY_VERSION — Constant

Oldest cuDensityMat release whose ABI the generated bindings match (cudensitymatCreateOperatorAction gained scopeKind/approachKind in 0.7).

source
CuQuantum.CuDensityMat.RK4_HALF_DISK_BOUND — Constant

Radius of the largest closed half-disk {|z| ≤ r, Re z ≤ 0} inside the RK4 stability region (minimum of rk4_stability_radius over angles in [π/2, π], attained near angle 0.68π). h · max|λ| ≤ RK4_HALF_DISK_BOUND is sufficient for every eigenvalue λ of a Lindbladian (all have Re λ ≤ 0), whatever their phases.

source
CuQuantum.CuDensityMat.RK4_REAL_AXIS_BOUND — Constant

Classic RK4 stability bound on the negative real axis: |R(z)| ≤ 1 for z ∈ [-RK4_REAL_AXIS_BOUND, 0], R(z) = 1 + z + z²/2 + z³/6 + z⁴/24 (the real root of R(z) = 1, z ≈ -2.785293563405282). For a real, negative dominant eigenvalue λ the step must satisfy h|λ| ≤ RK4_REAL_AXIS_BOUND.

CuQuantum.CuDensityMat.CpuLindbladian — Type
CpuLindbladian(spec; batch_size=1, num_params=0, merge=true)

Host executor of lindblad_plan(spec) on batched density matrices stored like cuDensityMat states (a vector of length n²·batchsize, member b = `vec(ρb)). Callable asL(out, x, t, params):out = L(t) x(overwritesout),paramsa(numparams, batchsize)` matrix. Each product is a pair of sparse full-space matrices (ket side, bra side); this is the reference backend for small dims and for tests.

CuQuantum.CuDensityMat.LindbladOperator — Type
LindbladOperator(ws, spec; batch_size=1, num_params=0, sparsity=:auto, merge=true,
                 split_terms=false, factor_order=:by_mode)

The cuDensityMat Operator of dρ/dt = L(t)ρ for spec, for states of batch size batch_size and num_params parameters per member (pass params as a num_params × batch_size column-major CuVector). One OperatorTerm per plan group: the static group is appended with append_term!; every coefficient function becomes a batched CPU scalar callback (append_term_batch!), so members can differ. Factors use MULTIDIAGONAL storage (sparsity=:auto unless the factor fills every diagonal, then dense; :multidiagonal / :dense force one kind). Each factor owns its elementary operator (share_elementary=true shares identical matrices across products; see the comment in the constructor for why this is off by default).

split_terms / factor_order are layout knobs (one OperatorTerm per product signature; factor order :by_mode or :ket_first) that give the same operator.

Fields: operator (the Operator), plan, dims, batch_size, num_params, num_elementary (distinct elementary operators), data_bytes (their device storage).

CuQuantum.CuDensityMat.add_hamiltonian! — Method
add_hamiltonian!(spec, coefficient, factors::Pair{Int,<:AbstractMatrix}...) -> spec

Add the Hamiltonian term coefficient * ⊗ factors (factors on the same mode are multiplied in the given order). coefficient is a Number (static) or a function f(t, p) -> Number of time and the batch member's parameter vector. The terms must add up to a Hermitian H; individual terms need not be Hermitian (e.g. g a†b and g ab†).

CuQuantum.CuDensityMat.add_jump! — Method
add_jump!(spec, rate, factors::Pair{Int,<:AbstractMatrix}...) -> spec

Add the dissipator rate * D[L], D[L]ρ = LρL† - ½{L†L, ρ}, with jump operator L = ⊗ factors. rate is a non-negative Real (static) or a function r(t, p) -> Real. (A rate folded into the operator, L = √γ a, is equivalent to rate = γ, L = a.)

CuQuantum.CuDensityMat.compute_operator_action_backward! — Method
compute_operator_action_backward!(ws, operator, state_in, state_out_adj,
    state_in_adj, params_grad; time=0.0, batch_size=state_in.batch_size,
    num_params=0, params=nothing)

Compute backward differentiation (the VJP) of a single-operator action ρ_out = A(θ) ρ_in.

Gradient convention

Adjoints are holomorphic-side gradients, ∂L/∂Re z − i ∂L/∂Im z (= 2 ∂L/∂z), the elementwise conjugate of the ChainRules/Zygote cotangent ∂L/∂Re z + i ∂L/∂Im z. For a real cost L(ρ_out) pass state_out_adj = ∂L/∂Re ρ_out − i ∂L/∂Im ρ_out; locally this is the bilinear cost L = Re Σᵢⱼ state_out_adjᵢⱼ ρ_out,ᵢⱼ = Re Tr(state_out_adjᵀ ρ_out) (the seed is not conjugated). Then:

  • state_in_adj += A(θ)ᵀ state_out_adj, the same kind of gradient with respect to ρ_in (chain it into the previous step's state_out_adj);
  • every gradient callback receives the holomorphic adjoint of its quantity Q (scalar coefficient or operator tensor), ∂(Σ state_out_adj ∘ ρ_out)/∂Q — for a scalar callback this includes the static coefficient it multiplies — and must accumulate params_grad[n] += Re(Σ adjoint .* ∂Q/∂θ[n]), with no factor 2.

To use a ChainRules cotangent ρ̄, pass conj.(ρ̄) and conjugate the returned state_in_adj; params_grad needs no change.

The cuDensityMat header documents 2·Re(...): that is the same number for the Wirtinger seed state_out_adj = ∂L/∂ρ_out, half of the seed above. The convention was measured on an A10 (libcudensitymat 0.7.0) and is pinned against finite differences of the GPU forward action, with factor-2, conjugation and conjugated-seed negative controls, in test/densitymat/test_gradients.jl.

Arguments

  • state_in: Forward-pass input state
  • state_out_adj: Adjoint of the forward-pass output, ∂L/∂Re ρ_out − i ∂L/∂Im ρ_out
  • state_in_adj: Output — receives ∂L/∂Re ρ_in − i ∂L/∂Im ρ_in (accumulated, += semantics)
  • params_grad: GPU vector — receives the parameter gradients from the gradient callbacks (accumulated, += semantics; zero it before the first call)

CuQuantum.CuDensityMat.create_operator_spectrum — Method
create_operator_spectrum(ws, operator;
    is_hermitian=true,
    spectrum_kind=CUDENSITYMAT_OPERATOR_SPECTRUM_LARGEST_REAL) -> OperatorSpectrum

Create an extreme-eigenspectrum (block Krylov) solver for the given operator.

Arguments

  • is_hermitian: Whether the operator is Hermitian (the library trusts the flag)
  • spectrum_kind: Which eigenvalues to compute:
    • CUDENSITYMAT_OPERATOR_SPECTRUM_LARGEST_REAL — largest real part (default)
    • CUDENSITYMAT_OPERATOR_SPECTRUM_SMALLEST_REAL — smallest real part
    • CUDENSITYMAT_OPERATOR_SPECTRUM_LARGEST — largest by magnitude
    • CUDENSITYMAT_OPERATOR_SPECTRUM_SMALLEST — smallest by magnitude

cuDensityMat 0.7 only implements Hermitian operators with the *_REAL kinds (the same two that cuQuantum Python exposes, as "LA"/"SA"); the by-magnitude kinds and is_hermitian = false make cudensitymatCreateOperatorSpectrum return CUDENSITYMAT_STATUS_NOT_SUPPORTED, which is rethrown here as an ArgumentError naming the supported configuration. The solver further needs non-batched dense pure states in double precision, and a Hilbert space larger than the Krylov subspace (see prepare_spectrum!).

CuQuantum.CuDensityMat.estimate_lambda_max — Method
estimate_lambda_max(rhs!, v, bufs, batch_size; t=0.0, power_iters=30, krylov_dim=6)
    -> (lambda, abs, ritz, power)

Per-batch-member estimate of the eigenvalue of largest modulus of the linear map rhs!(out, x, t) (out = L(t)x), from matrix-vector products only: power_iters normalized power iterations from v (overwritten), then a krylov_dim-step Arnoldi (modified Gram–Schmidt, per member) from the power iterate; lambda[b] is the Ritz value of largest modulus of member b. Power iteration alone does not converge when the dominant eigenvalues are a complex-conjugate pair (Lindbladians are Hermiticity preserving, so non-real eigenvalues come in pairs λ, λ̄); the Rayleigh–Ritz step resolves the pair. power[b] is the last power-iteration ratio ‖Lv‖/‖v‖.

bufs must hold krylov_dim + 1 arrays shaped like v. Ritz values lie in the field of values of L, not necessarily inside the convex hull of its spectrum (L is non-normal), so the estimate may land slightly on either side of |λ_max| (measured within ±10 % against dense spectra in the tests, typically ≤ 1e-3 relative); keep a safety factor in the step choice.

CuQuantum.CuDensityMat.lindblad_plan — Method
lindblad_plan(spec; merge=true) -> Vector{PlanGroup}

Lower spec to elementary products. Hamiltonian terms become a ket product (-i c P) and a bra product (+i c P); each jump becomes the sandwich γ (ket L, bra L†) and the anticommutator halves -γ/2 (ket L†L), -γ/2 (bra L†L) with L†L = ⊗ L_m†L_m. Terms with the same coefficient (nothing = static, or the same function object) share a group. With merge=true, single-factor products of a group on the same (mode, side) are summed into one factor matrix (e.g. Kerr, detuning and all -½L†L of one mode become one ket and one bra operator), which cuts the number of state passes per action.

CuQuantum.CuDensityMat.lindblad_rk4! — Method
lindblad_rk4!(ws, L::LindbladOperator, ρ::DenseMixedState, t0, t1; nsteps,
              params=nothing, params_fn=nothing, callback=nothing, cache=nothing) -> ρ

Integrate the batch ρ from t0 to t1 with nsteps classic RK4 steps (FP64) of the cuDensityMat Lindbladian L, in place. Per-member parameters: params (num_params × batch matrix, uploaded once) or params_fn(P, t), which fills the host matrix P in place at every stage time (it is then copied to the device). callback(ρ, t, step) runs after every step (return :stop to end early). Pass a LindbladRK4Cache to reuse buffers across calls.

Stability: choose h = (t1-t0)/nsteps with h·|λ_max| ≤ RK4_REAL_AXIS_BOUND for a real dominant eigenvalue, or rk4_stable_step of the estimate from lindblad_lambda_max in general.

CuQuantum.CuDensityMat.wrap_scalar_callback — Method
wrap_scalar_callback(f; gradient=nothing, device=:cpu) -> (cb, gcb, refs)

Wrap a Julia function as a scalar callback for time-dependent coefficients.

Arguments

  • f: the coefficient function. For device = :cpu, f(time::Float64, params::Matrix{Float64}, storage::Vector{T}) computes on the host; for device = :gpu, f(time::Float64, params::CuDeviceMatrix{Float64}, storage::CuDeviceVector{T}, stream::CuStream) enqueues CUDA.jl kernels on stream (e.g. @cuda stream=stream kernel(storage, params, time)) and returns without synchronizing. T matches the operator's data type, params is (numParams, batchSize) and storage is (batchSize,). Write the coefficient values into storage.
  • gradient: Optional gradient function, g(time, params, scalar_grad, params_grad) on the CPU, or g(time, params, scalar_grad, params_grad, stream) on the GPU. scalar_grad[b] is the holomorphic adjoint of the coefficient f, input only; the function accumulates params_grad[i, b] += real(scalar_grad[b] * ∂f[b]/∂params[i, b]) — Re, with no factor 2, in the gradient convention of compute_operator_action_backward!.
  • device: :cpu (CUDENSITYMAT_CALLBACK_DEVICE_CPU) or :gpu (CUDENSITYMAT_CALLBACK_DEVICE_GPU); applies to both f and gradient.

Returns

  • cb::cudensitymatWrappedScalarCallback_t — the callback struct
  • gcb::cudensitymatWrappedScalarGradientCallback_t — the gradient callback struct
  • refs — opaque reference holder (keep alive while callback is in use)

Example

# Time-dependent coefficient: f(t) = exp(iΩt) where Ω = params[1,:]
function my_coeff(time, params, storage)
    for i in axes(storage, 1)
        ω = params[1, i]
        storage[i] = complex(cos(ω * time), sin(ω * time))
    end
end
cb, gcb, refs = wrap_scalar_callback(my_coeff)

# The same on the GPU
function cis_kernel!(storage, params, t)
    i = threadIdx().x
    i <= length(storage) && (storage[i] = cis(params[1, i] * t))
    return
end
gpu_coeff(t, params, storage, stream) =
    @cuda threads=length(storage) stream=stream cis_kernel!(storage, params, t)
cb, gcb, refs = wrap_scalar_callback(gpu_coeff; device=:gpu)
